# mobile

The React Native half of the app. Expo SDK 57, TypeScript, dev builds.

It covers what the backend provides — sessions, subscriptions, remote config, push,
account deletion — so a new screen calls one function instead of re-solving token refresh
and error parsing.

## Running it

    cd mobile
    cp .env.example .env      # point EXPO_PUBLIC_API_BASE_URL at your backend
    npm install
    npm start

The Android emulator reaches your machine at `10.0.2.2`, not `localhost`. A physical device
needs your LAN IP.

`npm run typecheck` is this side's `mvnw verify` — with no test suite yet, the type checker
is what catches the API contract drifting from the backend.

## Layout

    src/
      platform/          everything the app needs before it does anything interesting
        core/            HTTP client, error contract, ports
        identity/        session, token refresh, device id, account deletion
        billing/         entitlements from our backend + the RevenueCat SDK
        appconfig/       remote config, force update, feature flags
        notifications/   push permission and device registration
        analytics/       event port with a no-op default
        bootstrap.ts     what happens at launch, in order
      domain/            YOUR APP. Ships empty.
    App.tsx              a shell that proves the platform is wired

It mirrors the backend in responsibility, not file-for-file. The client has no tables and
no SPI, so two server modules collapse: account deletion and export live in `identity`
rather than their own module, and quota needs nothing beyond the `quota_exceeded` code
`core` already exposes.

## The parts worth knowing

**Every call goes through `request()`.** That is what makes the cross-cutting behaviour
possible at all: one token refresh instead of one per screen, an `Idempotency-Key` on every
mutation, the platform and version headers, and a 426 from *any* endpoint reaching the
update gate. Scattering `fetch` calls would mean re-implementing each of those, badly.

**Refresh is single-flight.** When a token expires every in-flight request fails at once.
Without this each would start its own refresh and all but one would rotate a token another
had already replaced — which on a backend that revokes the old token logs the user out.

**Error codes are a shared contract.** `src/platform/core/api/errors.ts` and the server's
`ErrorCodes.java` are a pair. Branch on `code`, never on `message`.

**Entitlements come from our backend, not the RevenueCat SDK.** The SDK knows what the
store told this device; the backend knows what it verified server-side. The SDK is still
what you use for the paywall and the purchase itself.

**The session is in SecureStore**, not AsyncStorage — a refresh token is a long-lived
credential, and AsyncStorage is a plain file. It is also marked device-only, so restoring a
backup onto a second phone does not restore a live session.

**The device id is generated by us**, not read from the device. `identifierForVendor` resets
when the last app from a vendor is uninstalled, and the Android id resets on factory reset
or a change of signing key — either would silently strand an anonymous user's data.

## Before you ship

- [ ] Rename: `app.json` name/slug, `ios.bundleIdentifier`, `android.package`.
- [ ] Fill in the RevenueCat **public SDK** keys in `.env`. The secret key stays on the
      backend.
- [ ] Make a dev build (`npx expo prebuild`, then EAS or local). RevenueCat, Sign in with
      Apple and push all need native code, so Expo Go is not enough.
- [ ] Implement provider sign-in. `signInWithProvider` posts to the backend, but the
      backend's Apple and Google verifiers are still TODO — nobody can sign in until those
      land.
- [ ] Add push registration where it belongs in your flow. `registerForPush()` is written
      but nothing calls it; register on every launch, since tokens rotate.
- [ ] Swap the no-op analytics recorder for a real one, if you want analytics.

## What it deliberately does not do

- **No navigation, no state library, no design system.** `App.tsx` is a shell to delete.
- **No offline queue or cache.** Requests fail when the network does.
- **No paywall UI.** The RevenueCat SDK gives you offerings; the screen is yours.
- **No tests.** The type checker is the only gate today.
